# A spider web made of filaments.
#
# This network has a closed hub ring at the center, 8 radial spokes, and 5 rings
# of capture threads, with each ring made of 8 thread filaments between neighboring
# spokes. Every thread attaches by its minus end to one spoke and by its plus end
# to the same node of the next spoke, so each cell of the web is a closed loop.
#
# Smoldyn holds the attachments that form a tree exactly, and holds each remaining
# attachment, which closes a loop, with a spring. Here, the hub is the root of the
# tree, each spoke is pinned exactly to a hub node, and each thread is pinned
# exactly to the spoke at its minus end. The 40 thread plus ends, and the hub's own
# closure, are the loop-closing attachments, held by springs (junction_force). The
# diagnostics output at the start lists them.
#
# The hub's standard_angle makes it a ring (2*pi/16 per node). The spokes leave the
# hub at the branch angle pi/2 - pi/16 = 1.3744, and the threads leave the spokes at
# pi/2 + pi/8 = 1.9635 at both of their ends, which are the angles of the regular
# web, and branch_force_angle holds them there. The threads' segments are a little
# longer than their standard_length, so the threads are under tension, as in a real
# web; the tension pulls the spokes slightly inward between threads.
#
# A loop-closing spring passes its force through the rigid attachments to the hub,
# so each spoke carries the springs of the 10 threads that end on it or on its
# neighbors. The time step needs to be small enough that time_step * mobility *
# (sum of those spring constants) is well below 1, which is why junction_force is 30
# here; Smoldyn warns if it isn't.
#
# At time 30, something tears a hole in the web: two threads between spokes s3 and
# s4 are removed, and the next thread out breaks at its plus end, so it stays
# attached to spoke s3 by its minus end. The rest of the web relaxes around the
# damage.
#
# smoldyn spiderWeb2D.txt
